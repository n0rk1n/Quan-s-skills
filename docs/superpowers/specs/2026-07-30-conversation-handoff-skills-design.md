# 对话交接 Skills 设计

## 目的

为长时间运行的 Codex 任务提供一套可验证、可追溯的跨对话交接机制，降低上下文接近上限、发生压缩或早期事实逐渐丢失时的幻觉风险。

本设计包含两个配套 Skill：

- `creating-conversation-handoffs`：从当前对话和实时工作区状态生成自包含的 Markdown 交接快照。
- `resuming-from-conversation-handoff`：读取最新或指定快照，复核易变化事实并继续未完成任务。

交接文档是续接入口，不是完整对话副本。正文不足时，新对话可根据快照记录的旧对话 UUID，使用宿主提供的任务或会话读取能力回查原文。

## 目标

- 用户显式调用时生成交接；发现上下文明显过长、发生压缩或开始遗忘早期事实等信号时，只主动建议调用。
- 默认在当前项目或任务 worktree 的 `.codex/handoffs/` 中保存交接文件。
- 每次生成不可覆盖的时间戳快照，并通过 `LATEST.md` 提供稳定入口。
- 每个新快照完整自包含，同时记录相对上一个快照的变化。
- 用固定的事实状态和证据字段区分已验证信息、用户确认信息和待核实信息。
- 新对话读取后复核易变化事实，避免重复已完成工作，并直接继续首个可执行步骤。
- 信息不足时通过真实旧对话 UUID 回查；无法回查时明确报告，不猜测。
- 交接完成后只提醒用户手动调用 `archiving-to-devonthink`，不主动调用或归档旧对话。
- 通过结构校验、自动化测试、无 Skill/有 Skill 对照场景和端到端演练验证行为。

## 非目标

- 不自动监控或精确计算 Codex 上下文使用百分比。
- 不把交接文件当作原始对话导出或完整审计日志。
- 不生成、保存或转述私有思维过程。
- 不自动调用 `archiving-to-devonthink`，不关闭、归档或删除旧对话。
- 不根据旧快照直接相信 Git、文件、测试或外部服务的当前状态。
- 不实现依赖 Codex 内部 JSONL 格式的全自动摘要器。
- 不要求所有宿主提供旧对话读取能力；能力缺失时采用明确降级。
- 不用校验脚本理解或判断摘要内容是否正确。

## 方案选择

采用“`SKILL.md` + Markdown 模板 + 轻量校验器”的方案。

纯说明型 Skill 虽然简单，但较难稳定保证必填字段、索引更新顺序和事实状态。全自动会话导出器又会依赖宿主内部格式，容易引入重复工具输出、敏感信息和跨宿主兼容问题。

选定方案将语义工作和机械检查分开：

- Codex 根据当前对话、旧快照和实时证据完成事实筛选与摘要。
- 模板固定交接文件的正向结构。
- 校验器只检查文件契约，不替代语义判断。

## 包结构

### `creating-conversation-handoffs`

```text
creating-conversation-handoffs/
├── SKILL.md
├── references/
│   └── handoff-template.md
└── scripts/
    └── validate_handoff.py
```

职责：

- 说明触发条件、前置检查、事实核验规则、生成顺序和完成条件。
- 定义 `.codex/handoffs/`、时间戳快照和 `LATEST.md` 的行为。
- 使用模板塑造输出结构。
- 调用校验器检查候选快照和索引。
- 返回绝对文件路径、可复制的续接指令和手动归档提醒。

### `resuming-from-conversation-handoff`

```text
resuming-from-conversation-handoff/
└── SKILL.md
```

职责：

- 接受显式快照路径，或默认发现当前项目的 `.codex/handoffs/LATEST.md`。
- 安全解析索引和快照。
- 区分稳定信息和易变化信息，并复核后者。
- 识别首个可执行的未完成事项并继续任务。
- 必要时根据旧对话 UUID 回查原文。

读取 Skill 不依赖生成 Skill 的脚本才能理解快照。两个 Skill 可以分别被发现，但完整工作流要求同时安装。

### 仓库级内容

实现时更新仓库 `README.md`，列出两个新 Skill、安装方式、调用示例和它们的配套关系。自动化测试放在仓库现有 `tests/` 结构下，不把测试辅助内容放进运行时 Skill 正文。

## 触发模型

### 显式生成

用户命名或调用 `creating-conversation-handoffs` 时，Skill 直接执行生成流程。

### 主动建议

当代理观察到以下任一信号时，可以建议用户调用生成 Skill：

- 宿主明确提示发生上下文压缩或截断。
- 对话已经很长，且任务仍有多个后续步骤。
- 代理无法可靠复述早期已确认事实。
- 用户准备新开对话继续同一任务。
- 当前任务包含重要未提交状态、外部状态或多次失败尝试，丢失后恢复成本较高。

建议不是执行授权。未收到用户明确调用或确认前，不写交接文件。

Skill 不声称能读取精确的上下文百分比，也不以某个虚构的 90% 阈值作为触发依据。

### 显式读取

用户命名或调用 `resuming-from-conversation-handoff` 时：

- 提供路径则读取该路径；
- 未提供路径则查找当前项目 `.codex/handoffs/LATEST.md`；
- 找不到时询问准确路径，不扫描无关目录。

## 文件位置与命名

默认目录：

```text
<当前项目或任务 worktree>/.codex/handoffs/
```

生成操作必须遵守当前项目注入的 Git 和 worktree 规则。若当前项目要求所有仓库写入位于独立 worktree，则交接文件也必须写入当前任务 worktree；不能为了生成交接而污染主工作区。

时间戳快照：

```text
YYYY-MM-DD-HHmm-<topic-slug>.md
```

- 时间使用本地时区。
- `<topic-slug>` 使用简短、可识别、文件系统安全的英文或拼音短语。
- 同一分钟重名时增加稳定序号，不覆盖已有快照。

最新索引：

```text
LATEST.md
```

`LATEST.md` 是普通 Markdown 文件，不使用符号链接，以保持跨平台和跨宿主可读性。

## 交接快照契约

每个快照都必须完整自包含，包含以下顺序固定的章节。

### 元数据

元数据记录：

- schema 版本；
- 生成时间和时区；
- 任务摘要；
- 旧对话 UUID；
- 当前项目或 worktree 根目录；
- 上一个快照的相对路径，首次生成时为“不适用”。

UUID 必须来自可验证的宿主上下文、环境变量、任务工具或会话索引。无法取得时写明“不可用”及原因，不得编造。

### 续接摘要

用最短篇幅回答：

- 用户最终想完成什么；
- 当前已经到哪里；
- 现在最重要的约束是什么；
- 新对话应从哪一步继续。

新对话只读这一节也应能理解任务方向，但不得仅凭这一节跳过后续事实复核。

### 用户目标与验收标准

保留仍然有效的：

- 用户原始意图；
- 明确范围；
- 成功条件；
- 禁止事项；
- 交付与 Git 边界。

### 必须了解的背景

只记录会改变后续判断的信息。删除闲聊、重复解释、已经失效的中间猜测和与任务无关的上下文。

### 相对上次交接的变化

存在旧快照时，列出：

- 新完成内容；
- 新增或改变的决策；
- 发生变化的工作区或外部状态；
- 新阻塞项；
- 已失效的旧信息。

首次生成时明确写“不适用：这是首个交接快照”。

### 事实与证据

事实使用以下状态：

| 状态 | 含义 |
| --- | --- |
| `已验证` | 有当前文件、命令、工具结果、提交或其他可复查证据 |
| `用户确认` | 用户明确作出的要求或决定 |
| `待核实` | 可能影响任务，但当前证据不足 |

每项事实至少记录事实内容和状态。易变化事实还应记录证据来源或最后核实时间。推断只能进入“待核实”，不能伪装成已验证事实。

### 已完成事项

每项记录：

- 完成内容；
- 影响文件或外部对象；
- 验证命令或观察方式；
- 验证结果；
- 是否已提交、合并、推送或部署。

必须区分 focused test、完整测试、基线失败、提交、合并、推送、部署和外部执行，不用一个“已完成”覆盖不同状态。

### 当前工作区状态

适用时记录：

- 项目根目录；
- worktree 路径；
- 当前分支和目标分支；
- `HEAD`；
- 上游关系；
- 未提交文件；
- 与任务相关的关键文件；
- 最近一次相关测试或构建状态。

这些内容都是易变化事实。读取 Skill 必须实时复核，不能直接继承为当前事实。

### 决策与理由

记录已经确认的方案、关键取舍、被放弃的选项及原因。只保留会影响后续执行的理由，不记录私有思维过程。

### 失败尝试与避坑点

只保留：

- 已尝试但失败的方法；
- 可复查的失败表现；
- 失败原因或当前最佳判断；
- 后续不要重复的动作。

不粘贴大段原始日志。

### 未完成事项与下一步

按执行顺序记录。每一步尽量包含：

- 具体动作；
- 目标文件、模块或外部对象；
- 前置条件；
- 完成判据；
- 必要的验证命令。

第一个无阻塞步骤必须明确标记为“首个可执行步骤”。

### 阻塞项与待确认问题

只记录确实需要用户、外部系统或新权限才能解决的事项。能够通过当前工作区或只读工具查明的问题，不推给用户。

### 关键文件、命令与外部资源

提供继续工作需要的精确路径、命令、提交、任务 ID 或链接。不得记录密钥、令牌、密码或完整个人隐私。

### 来源信息与回查

记录：

- 旧对话 UUID；
- 生成时间；
- 上一个快照；
- 可用时的任务宿主或会话类型；
- 信息不足时按 UUID 回查旧对话的要求。

读取 Skill 应优先使用宿主提供的任务、线程或编码代理会话读取能力。无法读取时，只在缺失信息阻塞首个可执行步骤的情况下询问用户。

### 新对话续接指令

指令要求新对话：

1. 读取完整快照。
2. 复核易变化事实。
3. 报告影响执行的差异。
4. 不重复已完成事项。
5. 从首个可执行步骤继续。
6. 内容不足时按旧对话 UUID 回查。

## `LATEST.md` 契约

`LATEST.md` 仅包含：

- 最新快照的相对 Markdown 链接；
- 生成时间；
- 旧对话 UUID；
- 一句任务摘要。

它不复制完整快照内容。

快照链接必须：

- 使用相对路径；
- 解析后仍位于同一个 `.codex/handoffs/` 目录；
- 指向存在的普通 Markdown 文件；
- 不能指向 `LATEST.md` 自身；
- 不能通过 `..` 或符号链接逃逸目标目录。

## 生成数据流

1. 确认用户已显式调用生成 Skill。
2. 确认当前项目、任务 worktree、写入权限和适用的项目规则。
3. 发现旧 `LATEST.md` 时，安全解析并读取上一个快照。
4. 读取当前对话，获取真实旧对话 UUID。
5. 对 Git、文件、测试和外部状态等易变化事实执行与任务风险相称的实时核实。
6. 汇总仍有效的旧信息和本次新增变化。
7. 在安全临时位置生成候选快照。
8. 运行结构校验和敏感信息风险检查；修复后重新校验。
9. 将验证通过的候选快照写入最终时间戳路径。
10. 生成新的候选 `LATEST.md`，验证其目标后再替换旧索引。
11. 返回新快照绝对路径和可复制的续接指令。
12. 提醒用户在确认新对话成功续接后，可手动调用 `archiving-to-devonthink`。

生成失败时不更新 `LATEST.md`，也不声称交接成功。

## 读取与续接数据流

1. 确认用户已显式调用读取 Skill。
2. 使用用户提供的快照路径；未提供时解析当前项目的 `LATEST.md`。
3. 验证索引和快照路径安全。
4. 检查快照必填章节和 schema 版本。
5. 区分稳定信息与易变化信息。
6. 实时复核会影响首个下一步的 Git、文件、测试和外部状态。
7. 若快照与当前证据冲突，以当前证据为准并向用户报告差异。
8. 如果内容不足，按旧对话 UUID 使用可用任务或会话读取能力回查。
9. 用一句简短说明确认已恢复的目标、当前状态和首个可执行步骤。
10. 直接继续该步骤，除非存在确实需要用户决定的阻塞项。

读取 Skill 不修改快照、索引或旧对话，不自动执行破坏性操作。

## 事实新鲜度规则

默认视为相对稳定：

- 用户明确目标和验收标准；
- 用户确认的范围和禁令；
- 已记录的设计决策；
- 有提交或持久化证据的历史完成事项；
- 已验证的失败尝试。

默认必须实时复核：

- 当前目录和 worktree；
- 当前分支、目标分支、`HEAD` 和上游；
- 未提交状态；
- 文件当前内容；
- 测试、构建和诊断结果；
- 部署、任务、CI 和外部服务状态；
- 权限、工具和连接可用性；
- 时间敏感的信息。

复核成本与当前下一步无关且较高时，可以暂不复核，但必须继续标记为待核实，不能提升为当前事实。

## 安全与隐私

交接文件不得包含：

- 密钥、令牌、密码、Cookie 或连接凭据；
- 完整身份证件、手机号、邮箱等非必要个人隐私；
- 私有思维过程或隐藏推理；
- 无筛选的工具参数、工具返回和终端日志；
- 与续接无关的大段粘贴材料。

敏感信息只记录用途、变量名或安全来源位置，例如“数据库密码由环境变量提供”，不记录实际值。

校验器只能发现明显模式，不能证明文档绝对不含敏感信息。Skill 必须在写入前进行语义审查。

## 校验器边界

`validate_handoff.py` 使用 Python 标准库，提供适合自动化测试和人工调用的命令行接口。

校验内容：

- 文件名与扩展名；
- 必填章节及顺序；
- 元数据必填字段；
- 事实状态是否合法；
- 是否存在首个可执行步骤；
- UUID 字段是否为合法 UUID 或明确的不可用标记；
- `LATEST.md` 是否使用安全的相对链接并指向存在快照；
- 明显密钥、令牌和密码模式的风险提示。

不校验：

- 摘要是否语义完整；
- 事实是否真实；
- 决策是否合理；
- 下一步是否技术上正确；
- 敏感信息是否已被完全清除。

语义正确性由 Skill 的事实核实流程和场景测试保证。

## 错误处理

### 生成错误

- **项目或 worktree 不明确：** 在写入前询问准确位置。
- **目录不可写：** 报告限制并询问替代路径，不静默改写到其他项目。
- **旧索引无效：** 不信任其目标；报告问题，并在不覆盖不明内容的前提下生成独立快照。
- **旧对话 UUID 不可用：** 写明原因，继续生成其余内容。
- **候选快照校验失败：** 修复并重验；未通过前不发布。
- **最终快照写入失败：** 保留旧索引，报告失败。
- **索引更新失败：** 保留已验证快照和旧索引，返回新快照绝对路径并明确索引仍旧。
- **敏感信息风险未消除：** 停止发布，不能只给警告后继续。

### 读取错误

- **未找到索引或快照：** 询问准确路径。
- **索引路径逃逸或目标类型异常：** 停止，不读取目标。
- **快照结构不完整：** 报告缺失字段，不根据残缺内容盲目执行。
- **schema 不支持：** 报告兼容性问题，不猜测字段语义。
- **实时状态冲突：** 以当前证据为准，并在继续前报告影响。
- **旧对话回查失败：** 仅在缺失内容阻塞执行时询问用户。
- **下一步具有破坏性或需要额外授权：** 遵循当前项目和宿主的授权规则，不把交接文件视为授权。

## 与 `archiving-to-devonthink` 的关系

生成 Skill 只在以下条件全部满足后显示提醒：

- 时间戳快照已验证并发布；
- `LATEST.md` 已成功更新，或已明确返回索引更新失败和新快照绝对路径；
- 用户已获得可复制的续接指令。

提醒内容要求用户先确认新对话成功读取并续接，再手动调用 `archiving-to-devonthink`。

生成 Skill：

- 不加载或调用归档 Skill；
- 不导入 DEVONthink；
- 不归档、关闭或删除旧对话；
- 不把归档成功作为交接成功条件。

## 测试策略

### RED：无 Skill 基线

按照 `superpowers:writing-skills`，在写两个 Skill 前使用新上下文代理运行基线场景，并记录具体失败行为和原话。至少覆盖：

1. 长对话包含多次决策、部分过期 Git 状态和时间压力。
2. 已存在旧快照，本轮新增完成内容、改变决策并出现新阻塞项。
3. 对话包含敏感值、缺失 UUID 和大量无关工具输出。
4. 读取到结构残缺或状态过期的快照，同时被要求“不要检查，直接继续”。
5. 交接正文不足，但 UUID 可回查旧对话。

基线需要观察：

- 是否遗漏用户约束或已完成事项；
- 是否把推测写成事实；
- 是否相信过期状态；
- 是否泄露敏感信息；
- 是否无法指出首个可执行步骤；
- 是否在正文不足时忽略 UUID；
- 是否擅自归档旧对话。

### GREEN：加载 Skill 后复测

使用相同场景分别加载生成 Skill 和读取 Skill，验证：

- 输出结构稳定；
- 必填信息完整；
- 事实状态和证据边界明确；
- 快照自包含且正确描述相对变化；
- 读取时复核易变化事实；
- 正确回查 UUID 或明确降级；
- 不重复已完成工作；
- 不主动调用归档 Skill。

对行为塑形措辞按 `writing-skills` 要求进行带无指导对照组的多次微测试，人工检查每个被标记样本，避免只依赖关键词统计。

### 自动化测试

校验器测试至少覆盖：

- 合法首个快照；
- 合法累计快照；
- 缺失必填章节；
- 章节顺序错误；
- 非法事实状态；
- 缺失首个可执行步骤；
- 合法 UUID；
- 明确的 UUID 不可用标记；
- 伪造或格式错误 UUID；
- 合法 `LATEST.md`；
- 绝对路径、`..`、自引用和不存在目标；
- 明显敏感信息风险；
- 同分钟文件名冲突处理。

仓库现有测试必须继续通过。

### 端到端人工验证

1. 在隔离测试项目中准备一段包含已完成工作、未完成步骤、旧状态和可识别 UUID 的代表性对话上下文。
2. 使用生成 Skill 创建首个快照和 `LATEST.md`。
3. 增加新完成内容并再次生成，验证新快照自包含且包含相对变化。
4. 在新对话中调用读取 Skill，不提供显式快照路径。
5. 验证它从 `LATEST.md` 找到正确快照、复核当前状态、报告过期信息，并定位首个未完成步骤。
6. 删除正文中的一项必要细节，验证它能根据 UUID 回查；关闭读取能力后，验证它只在确实阻塞时询问用户。
7. 确认整个流程没有自动调用 `archiving-to-devonthink` 或归档旧对话。

## 成功标准

- 两个 Skill 均可被 Codex 发现，名称和描述符合 Skill 规范。
- 用户可在当前任务 worktree 的 `.codex/handoffs/` 生成不可覆盖的时间戳快照。
- `LATEST.md` 始终指向最后一个验证通过的快照，或明确保留旧索引并报告失败。
- 每个新快照都完整自包含，并说明相对上一个快照的变化。
- 快照明确区分已验证、用户确认和待核实信息。
- 新对话只需读取最新快照即可理解任务并继续首个可执行步骤。
- 易变化事实在执行前得到复核，过期内容不会被当作当前事实。
- 正文不足时可使用真实旧对话 UUID 回查；不可用时明确降级。
- 交接和续接过程中不泄露敏感信息或私有思维过程。
- 生成 Skill 只提醒手动归档，不主动调用 `archiving-to-devonthink`。
- 校验器、仓库测试、场景对照测试和端到端人工验证全部通过。
